## 一、场景与目标用户

### 1.1 目标用户

- **首版唯一真实使用者：我本人。**【既定】高校学生，日常同时处理课内学习、考试复习、组内科研、生活维护与有意识娱乐；主要设备为 Android 手机；当前用 Hermes + feishucli 安排日程，用 Simple Time Tracker 记录时间；需要随时打开应用处理临时发生的事情（《产品构想》2.2、2.3、2.4）。
- **第二阶段用户：高校学生群体。**【待决】具体画像、进入第二阶段的条件与扩大人群后的取舍尚未确定（《产品构想》2.2、8.2）。
- **非目标用户边界：**【建议】首版不面向团队协作、共享日历、管理他人任务或需要服务端账号的场景。

### 1.2 核心使用场景

| 编号 | 场景 | 起点与过程 | 期望结果 |
| --- | --- | --- | --- |
| S-01 | 每日开始 | 打开应用，默认进入今日概览，查看今日待办、近期日程、当前计时与今日时间统计 | 不需要切换多个页面即可决定接下来做什么 |
| S-02 | 临时收集 | 进入待办页新建任务，只填标题写入收件箱，不要求补全其他字段 | 事项不丢失，稍后可澄清 |
| S-03 | 澄清与组织 | 从收件箱判断是否需要行动，把多行动事项归入项目，把具体行动放入下一步行动／等待中／将来／也许 | 每一项只出现一次，归属清楚 |
| S-04 | 对话安排 | 给出次日多个明确时段，要求 AI 实际写入日程；安排不合理、需要选时或与现有日程冲突时，AI 指出并给方案 | 日程真实保存，冲突提前暴露 |
| S-05 | 到点执行 | 收到提醒后由我主动开始计时；默认并行记录多项，也可切换单活动模式 | 计时由我启动，状态与记录符合所选模式 |
| S-06 | 忘记计时 | 事后补录一条时间日志，修正分类、起止时间或关联任务 | 记录与统计被更正，不伪造精确数据 |
| S-07 | 查看分布 | 查看某日时间分布，或“过去一周”等范围的统计 | 数字可解释，不把时长当成果 |
| S-08 | AI 复盘 | 请 AI 分析过去一周的时间记录与结项情况，得到有数据依据的改进方向，并继续对话落实为待办或日程 | 建议可执行，不生成泛泛总结或生产力评分 |
| S-09 | 误操作回退（后期增补） | AI 批次写入有误，撤销最近一批对待办、日程的创建、修改、删除 | 首版不验收；后续恢复数据，冲突时停止而非覆盖 |
| S-10 | 课程导入 | 从教务来源导入课程表，技术路径待定；导入前预览校验，结果只进入日程，不进入待办 | 课程日期与时刻可核对；待办数量不变 |
| S-11 | 中断恢复 | 计时中锁屏、切到后台、从最近任务划掉或设备重启，之后重新打开 | 运行中的计时按开始时刻继续；暂停中的保持暂停；已记录数据不丢失 |
| S-12 | 备份与恢复（后期增补） | 导出备份，重装应用后恢复 | 首版不验收；后续保证业务数据、设置与个人记忆完整，不泄露密钥 |
| S-13 | 事务重心 | 给待办打标签后，请 AI 按未结项与指定周期结项两组标签占比分析事务重心 | 有数据依据，不生成生产力评分 |
| S-14 | 切换 GTD 清单 | 待办页大标题下是当前清单标题与内容，两者分界为“当前清单上缘”；下拉超过阈值后上缘下移、整清单下移，露出 GTD 选择页；左右横滑切换分区并更新清单 | 选择页保持，点击当前分区或上拉收起；条目仍可左右滑完成/放弃 |
| S-15 | 查看日志与统计 | 日志页记录层下拉进入统计层；统计层底部上拉回记录层；当前计时在两层都悬浮；边界处有提示 | 记录、统计与日期范围一致，计时不因切换消失 |
| S-16 | 调整日程密度 | 日程页双指缩放时间轴，缩小到全天覆盖全屏 | 只改变显示密度，不改日程数据 |
| S-17 | 悬浮导航 | 一级页面内容上滑时底部导航隐藏，下滑时显示；页面顶部下拉优先触发 GTD/日志切换 | 导航不遮挡内容，切页后恢复显示 |

### 1.3 首版不覆盖的场景

Obsidian 笔记与正式复盘、飞书或手机系统日历同步、应用内教务登录与抓取课表、多设备实时同步、多人协作、学习社区运营、本地运行大模型、以时间日志自动判定任务完成。首版不采用看板视图；不做四象限、撤销、备份恢复与调课行为（后期增补）。首版不做待办拖到日程或拖动改期（后期增补）。

### 2.2 首版明确不做

- 与 Obsidian 同步或集成；资料／笔记库（3、4.1）。
- 接入飞书或手机系统日历；应用内教务登录与直接抓取课表（5.1、5.2）。
- 账号体系、跨设备同步、云端同步服务（8.2）。
- 导入 Simple Time Tracker 历史记录（6.1）。
- 子任务层级（4.2）。
- 完整的逐项澄清向导、项目检查与回顾向导（4.1）。
- 看板视图；手机横置空间不足，以按项目分组的列表替代（第 10 项）。
- 四象限视图、撤销、备份恢复与调课行为；均为后期增补（第 13、15、19 项）。
- 待办拖到日程或拖动待办改期；后期增补（第 6 项）。
- 底部导航顺序自定义；首版顺序固定为今日、日志、待办、日程、设置。
- 顶部记录/统计切换；首版只用记录层下拉、统计层上拉切换。
- 空白/标题区左右滑切换 GTD 清单；首版只在 GTD 选择页内横滑切换。
- AI 底部入口或关闭 AI 入口；首版固定浮动按钮。
- 任意标签筛选；首版只做日程标签筛选与待办标签分类，不做待办标签筛选（5.1）。
- 高级图表与更多统计维度（6.4）。
- 多模型服务商、自定义兼容接口、本地模型（7.1）。
- 默认定期后台 AI 分析或主动重排日程（7.3）。
- 无限撤销历史、任意版本恢复、全部手动操作的回收站（7.4）。
- 精确超期率、以未勾选或无日志推断拖延、以时长或数量形成生产力评分（4.4、6.4）。
- 把未记录时段自动归为 Drift（6.3）。
- 提醒自动改期、自动结束任务或自动结束计时（5.3）。

### 2.3 后期增补与后续方向

**后期增补（首版不实现、不验收，保留需求与失败记录）**

- 四象限视图；可按截止日期与优先级自动分配，允许手动调整，AI 可建议。
- 最近一批 AI 对待办、日程的创建、修改、删除的撤销。
- 备份与恢复，包括敏感信息边界。
- 重复导入后的调课行为。
- 待办拖到日程管理直接创建日程；不自动编排时间；在日程页拖动待办可改日期/时间。
- 更丰富统计维度与高级图表。

**后续方向**

从自用推广到高校学生；电脑端、跨设备同步、账号／同步服务；应用内教务登录与更多学校适配；更多专注技巧与排程设定；任意标签筛选；外部日历接入；更多模型接口或协议（8.2）。以上均不纳入首版验收。

## 十、术语与口径

| 术语 | 口径 |
| --- | --- |
| 待办／任务／行动 | 一条可独立标记完成或放弃的事项；行动是位于 GTD 组织位置中的任务 |
| 项目 | 归集为达成一个结果需要推进的多个行动；首版不作为任务容器重复生成行动 |
| 结项 | 标记完成或标记放弃；未结束事项不算结项 |
| 完成率 | 完成数÷（完成数＋放弃数），按标记日期归入统计周期 |
| 日程 | 保存固定约束或时间预算的时间段，可关联待办，也可独立存在 |
| 时间边界 | 日程或时间预算的结束时刻，用于提醒与复核，不等于任务完成 |
| 时间日志 | 带分类、可关联任务、有起止时间的记录 |
| 单活动／并行 | 两种互斥计时模式；同一时刻只能启用一种；首版默认并行 |
| 暂停/继续 | 用户主动操作；暂停期间不计时，暂停状态跨重启保持 |
| 墙钟计时 | 运行中按开始时刻到当前的真实时间计算，关闭/重启期间计入 |
| 标准页 | 待办默认的按项目分组列表；项目任务列在各自项目下，单独任务单列 |
| 当前清单上缘 | 当前清单小标题与大标题之间的分界；下拉位移以它为基准 |
| GTD 选择页 | 下拉后在大标题与当前清单之间露出的分区选择层；横滑切换分区并保持 |
| 记录层/统计层 | 日志页的两个纵向层；记录层下拉进统计层，统计层底部上拉回记录层 |
| 悬浮底部导航 | 悬浮于内容上方、按滚动方向隐藏/显示的底部导航 |
| 2.2 清单 | 已由 v0.5 的“当前清单上缘＋GTD 选择页”模型替代，旧称谓仅保留在变更记录 |
| 条目滑动 | 待办/项目条目左滑完成、右滑放弃；条目上的滑动优先于选择页横滑 |
| 今日时间统计 | 首页模块；默认完整饼图，按父级分类＋未追踪展示今日占比 |
| 未追踪时间 | 24 小时减去当日已记录时段的去重覆盖时长；不为负 |
| 记录/统计切换 | 日志记录层下拉进统计层、统计层底部上拉回记录层；不设顶部切换 |
| 底部弹出层 | 详情和二级菜单自底向上弹出，点击上方或下滑关闭 |
| 待办标签／日程标签 | 两个独立标签体系，同名不互通；待办标签用于待办内部分类 |
| 两级分类 | 父级/子级；记录可挂任一级，统计按父级汇总，父级直属单列 |
| 仅本次/此事件及后续/整个系列 | 重复事项的三种修改删除范围；后续会分割系列 |
| 最小请求 | 只发送当前对话所需的待办/日程/日志摘要，不发送全库 |
| 设计默认项 | 需求约束已确认，具体手感/方案由架构/设计集中提出，增量验收时确认 |
| 确认版 | v1.0：需求范围、业务规则与验收条件已确认；不代表已实现或已验收 |
| 事务重心 | AI 按待办标签数量占比给出的两组分析：未结项待办、指定周期结项任务 |
| 后期增补 | 保留需求、首版不实现/不验收的条目，不得写成已完成或已删除 |
| 日志 | 底部导航中的时间日志入口 |
| 撤销批次 | 一次 AI 请求产生的写操作集合，具体边界待 OD-09；后期增补 |
| 个人记忆 | 经我确认后长期保存的作息、目标、偏好等信息 |
| 来源 | 课程表或普通日程，用于显示筛选，不按创建时间判断 |
| AC／BR／FR／OD／RC | 验收条件／业务规则／功能需求／未决事项／需求变更记录 |

首版不使用“任务状态字段”或“状态分组”；相关撤回原因保留在 RC-17。
